Overview

A command-line tool for Linux. It takes a JPEG, PNG or MP4 and finds heads with a YOLOv8-format ONNX model through OpenCV's DNN module. It then applies a glitch, pixelate or blur effect inside a feathered head-shaped mask. Images are written as JPEG or PNG; video is written as H.264 in MP4. The effects are artistic and are not guaranteed anonymisation, because the detector can miss heads.

It is a C++17 port of the processing core of an earlier Censface project of mine: an Android app and a Python reference program, neither published. The detector settings, tracker and effect formulas were ported with the same parameters. All video input and output was rewritten against the FFmpeg C libraries.

Implementation

One video goes through a single pass in VideoProcessor (src/video_pipeline.cpp):

  1. Demux and decode. avformat_open_input, av_find_best_stream, then avcodec_send_packet/receive_frame on the video stream.
  2. Convert. libswscale turns the decoded YUV frame into a BGR cv::Mat. Colour matrix and range come from the decoder (sws_setColorspaceDetails).
  3. Rotate. The display matrix from AV_PKT_DATA_DISPLAYMATRIX is applied to the pixels, so phone portrait clips come out upright with no rotation tag.
  4. Detect, track, filter. 640 px letterbox, score threshold 0.38, NMS 0.45, up to 64 heads. Boxes are smoothed between frames, and a lost head fades out over 0.18 s.
  5. Convert back and encode. BGR goes to yuv420p and into libx264 (veryfast, CRF 18, no B-frames). The encoder uses the input stream's time base, and each frame keeps its best_effort_timestamp, so variable-frame-rate clips keep their timing.
  6. Mux. Audio packets are copied unchanged when avformat_query_codec says MP4 can hold the codec; otherwise the audio is dropped with a warning.

Only one decoded frame is held at a time, and nothing but the output file is written to disk.

Architecture

  • main.cpp: argument parsing, path checks and SIGINT handling (exit 130).
  • image_pipeline.cpp, video_pipeline.cpp: the two processing paths.
  • face_detector.cpp: pre- and post-processing around cv::dnn::Net.
  • filters.cpp: glitch, pixelate and blur, and the mask.
  • ffmpeg_raii.h: a std::unique_ptr with a custom deleter for each FFmpeg object, so cleanup also happens when an exception unwinds.
  • scripts/batch.sh mirrors a folder tree into results and per-file logs. scripts/verify_video.sh compares timestamps and audio with ffprobe.

Technical decisions

  • The original Python program decoded with PyAV and then muxed audio back with an ffmpeg subprocess. This version does demux, decode, convert, encode and mux in one process.
  • Inputs are never overwritten. Output goes to a temporary file that is renamed only on success; an existing output needs --overwrite.
  • The build uses -Wall -Wextra -Wpedantic and finds FFmpeg through pkg-config, OpenCV through CMake.

Results / Validation

Checks recorded in the repository README, run by hand on the development machine (FFmpeg 9.0.2, OpenCV 5.0.0, GCC 16):

  • A 2 s H.264 and AAC clip: 24 of 24 frames with identical timestamps, audio packets byte-identical by MD5.
  • A rotated variable-frame-rate clip: correct output size, no rotation tag, timestamps and duration preserved.
  • Peak memory 486 MB for a 6 s clip and 490 MB for the full 29 s clip of the same 720p HEVC video. Memory does not grow with length.
  • Glitch output against the Python reference: 41.5 dB PSNR.

There is no automated test suite, and processing speed was not benchmarked.

Limitations

  • Detection runs on the CPU on every frame, with no frame skipping.
  • The head model has false positives and misses.
  • Output is always 8-bit H.264 yuv420p. HDR input is rejected.
  • Subtitles, data tracks and container metadata are not copied.
  • Tested on one Linux distribution only.
