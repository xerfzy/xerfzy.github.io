Multi-UAV Monitoring Prototype

Flask and Socket.IO ground-station prototype with simulated UAV telemetry, waypoint missions, return-to-home on low battery, polygon geofencing and ORB keypoint overlays on recorded video feeds.

Overview

A browser-based ground-station prototype for watching and commanding several UAVs at once. All aircraft and telemetry are simulated; no real UAV, flight controller or radio link is involved. A Flask server runs the simulation and pushes state to the dashboard over Socket.IO. A second part streams recorded video with ORB feature points drawn on each frame.

This is related engineering work for the published patent application IN202641060337 A1. The application describes much more than this prototype does. See Scope.

Implementation

  • Simulation (models/uav.py, services/uav_simulator.py). Six simulated aircraft, fixed-wing and quadcopter types, each with a home position, generated waypoint missions and a per-type cruise altitude and maximum speed. Each tick moves an aircraft toward its waypoint by bearing, eases altitude, drains battery or fuel, and switches to return-to-home below 15% battery. Loiter and pause states are also simulated.
  • Geofencing (services/geofence_manager.py). Polygon fences checked with a ray-casting point-in-polygon test on every update. A violation is sent to the dashboard as an alert.
  • Server (app.py). Flask routes for login, the dashboard and JSON APIs (aircraft, missions, geofences, video feeds). A command endpoint handles pause, kill and return-to-base with a role check. A background thread steps the simulation and emits uav_update events over Flask-SocketIO.
  • Video feeds. One thread per recorded MP4 reads frames with OpenCV and runs an ORB extractor (python_orb_slam3 if installed, otherwise cv2.ORB_create(nfeatures=2000)). It draws the keypoints, encodes JPEG and emits frames to the browser as data URLs.
  • Front end. Plain JavaScript dashboards with a Leaflet map for positions and fences.

Scope: what this does not implement

The patent application describes a drone swarm with stereo cameras, LiDAR, IMU and GPS; onboard and collaborative SLAM; peer-to-peer links within the swarm; crowd-flow estimation; anomaly validation; collision avoidance; and failover when the central link is lost. None of these are implemented in this repository. The prototype covers a simulated monitoring and command interface and ORB feature extraction on video.

A related experiment, ESP32-CAM ORB Features, runs ORB keypoint extraction on a live ESP32-CAM stream. That too is feature extraction only, with no tracking or mapping.

Limitations

  • All telemetry is generated by the simulator.
  • Prototype-grade configuration: demo login, a fixed secret key and permissive CORS. Not suitable for deployment as is.
  • The repository also contains an unused Next.js scaffold, which is why GitHub lists TypeScript as its main language.
